# Plan: Fix explode open/close bug + full 3D detail package

## Context
Slide 7's explode works opening but **close is broken**: the tick loop lerps each part from its *current* position every frame (`base = g.position.clone()`), so as the explode factor eases back to 0 the lerp target becomes the position itself — parts freeze wherever they were. In live use: explode once, close, and the car stays scattered (also after visiting the exploded payoff slide). Approved via grill: fix the bug, staged springy explosion, full detail package.

## 1. Root-cause fix (`.frontend-slides/src/deck.part2.html`)
- Capture fixed assembled bases at build: `EXPLODE_BASE = { engine: (-1.55,0.85,0), chassis: (0,0.75,0), cabin: (0.35,1.5,0) }`.
- Per-frame: `g.position.copy(EXPLODE_BASE[kk]).lerp(EXPLODE_POS[kk], k)` — deterministic; close always returns home. (Wheels already used this correct pattern via `userData.bx/bz`.)
- Replace `st.explode`/`explodeTarget` with a per-part staged progress (next section); the cartridge's ride-along formula switches to the cabin's progress value.

## 2. Staged springy explosion
- Open order: wheels → engine → chassis → cabin, 0.14s stagger, 0.65s each, `easeOutBack` (slight overshoot = springy).
- Close: reversed stagger, smooth ease. One `explodeClock` resets on every toggle/scene entry; S13 (`exploded`) forces open, showcase resets closed.
- Cabin explode target → (2.9, 1.5, 0): verified by screenshot to never cover the title/hint/button.

## 3. 3D detail package (all primitives, binary palette, attached to the right parents so they explode along)
